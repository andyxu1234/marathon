Overview

项目概览

背景、方案与关键工程决策

全栈 · 赛事工具 Taro 4 + React 18 + FastAPI 独立开发（小程序 / 服务端 / 数据管道 / 设计系统）

面向马拉松爱好者的赛事查询与个人追踪工具：把「找赛事 → 判断要不要报 → 盯报名 / 缴费 / 中签 → 沉淀个人战绩」 这条散落在十几个公众号与网页里的链路，收进一个六个页面的小程序里。

前端是 Taro 4.1 + React 18 + TypeScript，一套代码跨编译微信小程序与 H5；后端是 FastAPI + SQLAlchemy 2.0 异步服务（7 张业务表 / 26 个端点 / 7 个 Alembic 迁移版本），提供赛事列表与多维筛选、关注收藏、 报名状态流转、跑者排行、个人战绩统计与配置字典六组接口。数据不靠人工整理，而是一条 「列表卡片抓取 → LLM 联网补全 → 二轮筛选 → 增量 diff 入库」的富化管道， 由 APScheduler 每天定时跑，原始数据全程留痕可审计。

核心工作与亮点

  • 赛事数据富化管道：抓取最酷赛事列表卡片后，用 LLM 联网补全缺失字段，再做二轮筛选与字段级 sha1 增量 diff （zuicool_event_id 为增量键），只对新增或卡片字段变化的赛事重新富化，原始卡片 / 富化 / 最终三态 JSON 全量留痕。
  • 确定性与可审计优先：规则解析负责结构化字段，AI 只在规则失效时兜底；每条原始数据落 mi_event_source 表，保留来源 URL、抓取时间与内容哈希，字段来源可回溯。
  • 报名状态三维建模：把「报名 / 缴费 / 中签」拆成三个独立状态维度落在 mi_registration 表， 关注页用 chips 随手切换，并反算开赛倒计时；同一张表同时承载完赛时间、参赛号码与 PB 标记，驱动个人战绩与排行榜。
  • 跑者排行实时聚合：总跑量 / 半马 PB / 全马 PB / 总花费四个指标，官方赛事与自定义赛事两条数据来源合并， 按比赛类型推算里程（全马 42.195 / 半马 21.0975 / 健康跑 5 / 越野 30），并支持性别与年龄段筛选。
  • 一套代码两端 + 原生登录闭环：Taro 同一份代码编译微信小程序、抖音小程序与 H5； 小程序走 Taro.login → 后端换 openid → JWT 静默登录，H5 保留密码登录用于本地调试。
  • 自建设计系统「晨曦跑道」：珊瑚橙 × 青柠双主色 + 暖白纸面层级，设计 token 全部落到 SCSS 变量并自动注入每个样式文件， 入场动效以 mixin 收敛，保证 6 个页面视觉语言一致。

Data Pipeline

赛事数据是怎么来的

不靠人工整理，也不把整条链路交给 AI：确定性规则负责结构化解析，LLM 只在字段缺失时联网补全， 每天定时增量跑一次。

STEP 01

抓取列表卡片

适配器抓取最酷赛事列表页，规则解析出赛事名、开赛日期、地点、报名窗口、报名链接与封面图， 产出标准化候选对象。

STEP 02

LLM 联网补全

把卡片原始 JSON 交给 LLM 联网检索，补齐简介、路线、主办方、报名费等缺失字段， 再做二轮筛选过滤噪声，得到最终 JSON。

STEP 03

增量 diff 入库

以赛事 ID 为增量键、关键卡片字段的 sha1 哈希判断内容是否变化，只对新增或变化的赛事重新富化， 原始 / 富化 / 最终三态 JSON 全量留痕，再 upsert 进正式赛事表。

APScheduler 每日 06:30 防重入 + 错过补跑 来源权重与匹配状态可审计 手动触发接口 + 运行报告
Architecture

技术架构

前后端分离，数据管道独立成层，可单独触发与观测

Frontend

  • Taro 4.1 跨端框架（微信 / 抖音 / H5）
  • React 18 + TypeScript 5
  • Zustand 管理登录态
  • Taro.request 封装（重试 · 超时 · 自动鉴权）
  • Sass 设计 token 全局自动注入
  • 原生 TabBar + 自绘视觉，规避双渲染

Backend

  • FastAPI 0.115 + Uvicorn
  • SQLAlchemy 2.0 异步 ORM
  • MySQL 8（Windows aiomysql / Linux asyncmy）
  • Pydantic 2 请求响应模型
  • JWT 认证 + 微信 / 抖音 / 密码登录
  • Alembic 版本化迁移（7 个版本）

Data Pipeline

  • httpx 异步抓取 + Tenacity 指数退避
  • BeautifulSoup4 + lxml 规则解析
  • LLM 联网富化 + 二轮筛选
  • 字段级 sha1 增量 diff
  • 原始数据三态 JSON 留痕审计
  • APScheduler 定时调度 + 手动触发

Engineering

  • TTLCache 筛选项内存缓存
  • loguru 结构化日志
  • 构建产物自动修正脚本
  • 启动 / 停止 / 重启脚本
  • 设计稿 HTML 原型对齐还原
  • 服务端与客户端分离部署
